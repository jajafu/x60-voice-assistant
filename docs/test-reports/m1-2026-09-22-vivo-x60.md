## 已執行結果

| 項目 | 結果 | 證據摘要 |
|---|---|---|
| 固定模型 provisioning | 通過 | 官方 archive 下載後符合固定 archive SHA256；選用 encoder、decoder、joiner 與 tokens 的逐檔 SHA256 全部相符。模型 binary 保持 Git ignored。 |
| USB 安裝與冷啟動 | 通過（中間版 APK） | OriginOS 側載風險畫面確認後，package 顯示 versionCode 2／`0.2.0-m1`，Activity 顯示 M1 診斷頁。 |
| 啟動前不錄音 | 通過 | Activity 可見但未按按鈕時，`dumpsys activity services` 為 `(nothing)`；AppOps 沒有 running；`dumpsys audio` 只有前一輪的歷史 event，沒有 active recorder。 |
| 只能由可見 Activity 操作啟動 | 通過（ADB 模擬畫面點擊） | 由前景 Activity 的「啟動常駐 KWS」按鈕觸發；ServiceRecord 記錄 `createdFromFg=true`、caller state `TOP`、`allowWhileInUsePermissionInFgs=true`。未建立 BootReceiver 或其他背景啟動路徑。此輪不是手指實際點擊。 |
| microphone FGS | 通過 | Service `isForeground=true`、notification id 1001、PUBLIC visibility、1 個停止 action。 |
| 唯一 AudioRecord 與格式 | 通過（時間點檢查） | `dumpsys audio` 只有一個屬於 package 的 active recorder：`VOICE_RECOGNITION`、1 channel、16000 Hz、`ENCODING_PCM_16BIT`。未觸發 MIC fallback。 |
| Audio Frame 持續 | 通過（短時） | 診斷頁 16 秒時為 787 frames，78 秒時為 3,887 frames，約符合 20 ms frame 速率；Service Uptime 持續增加。 |
| WakeLock | 通過（短時） | `dumpsys power` 顯示唯一 `PARTIAL_WAKE_LOCK 'com.jajafu.x60assistant:VoiceKws'` 由 app uid／pid 持有。 |
| 本機 KWS 路徑 | 部分通過 | 中間版以 Windows `Microsoft Hanhan Desktop - Chinese (Taiwan)` 合成 3 次得到 1 次事件。最終 APK 在 `mWakefulness=Asleep` 時，以 rate -2 至 +2 合成 5 次，Wake Count 由 0 增至 6，Timestamp 更新，configured boost 1.50。這證明鎖屏模型事件路徑可工作，但多於刺激次數，可能是同一句重複觸發或播放環境因素，必須用真人語料調校；不能視為召回率通過。 |
| 提示音 | 程式路徑執行；未完成人耳驗證 | 命中 callback 會呼叫固定 `TONE_PROP_ACK` 120 ms；本輪無人在裝置旁獨立確認聲音，不能宣稱音量／聽感通過。沒有 TTS API。 |
| Audio Error | 通過（短時） | 診斷頁在 78 秒時為 0。 |
| Dropped Frame | 通過（短時） | 最終 APK 的 Service dump 在 170 秒／8,455 frames 時為 0；queue unit test 另驗證滿載時固定丟最舊並累計。 |
| 鎖屏仍錄音與 KWS | 通過（短時） | `mWakefulness=Asleep` 時 AppOps 持續 `RECORD_AUDIO ... (running)`，Audio Frame 增加，合成刺激令 Wake Count 更新。未達 30 分鐘或 8 小時。 |
| 強制停止釋放 | 通過（系統路徑） | `am force-stop` 後 Service 消失，AppOps 不再 running，audio event log 出現 recorder release，WakeLock event log 出現 REL；App 未自行復活。這不取代 App 通知停止 action 測試。 |
| 原始音訊不上傳 | 通過（結構檢查） | 最終 APK 沒有 `INTERNET` permission；程式只有記憶體 frame queue，沒有 PCM 檔案／資料庫／上傳實作。 |
| 短時最終診斷 | 通過（170 秒） | `audio_frames=8455`、`wake_count=6`、`audio_errors=0`、`dropped_frames=0`、`audio_source=VOICE_RECOGNITION`、WakeLock held、last error 空。 |
| 短時溫度狀態 | 記錄完成，不是耗電測試 | USB 供電；開始約 99%、29.5°C，最後 100%、30.3°C；Thermal Status 0，CPU sensors 約 32–33°C。測試太短，不能推論八小時耗電或熱穩定。 |

## 尚待執行，不宣稱通過

- 由真人在可見 Activity 以手指按啟動，以及從通知按「停止」後確認 AudioRecord、WakeLock、Service、通知全部釋放。
- 鎖屏說「小助手」並由人在現場確認 120 ms 提示音。
- 一公尺真人 20 次、至少三位說話者，目標至少 18 次成功。
- 安靜環境連續 8 小時誤喚醒測試。
- 接電熄屏連續 8 小時，結束後連續三次喚醒。
- 未接電熄屏連續 8 小時，以及實際耗電、溫度與 thermal status 記錄。
- 電視背景 8 小時與三公尺 20 次調校資料。
- 完整 8 小時結束時的 Service Uptime、Audio Error、Dropped Frame 與 Wake Count。

## 可重現步驟

依 [`docs/testing.md`](../testing.md) 先準備模型、建置並用指定 serial 安裝。每個長測試開始前記錄 commit、APK／model SHA256、電量、溫度、thermal status、充電與 Wi-Fi；開始服務後確認唯一 `VOICE_RECOGNITION` recorder，鎖屏並記下開始時間。結束時先說三次「小助手」，再解鎖擷取診斷頁與 `dumpsys`；任何不足八小時、中途重裝／重開機或缺少結束證據的輪次都標記未完成。

# Issue Plan 範本

將下面內容貼到該 Issue。小修正可每項寫一句；資料遷移、權限或公開 API 等高風險變更再補細節。尖括號是**每個 Issue 當次填寫**，不是專案參數。

```markdown
## Plan

- 目標與範圍：<要完成什麼；本次不做什麼>
- 做法：<預計修改哪些部分>
- 驗收：<完成後如何判斷正確>
- 測試：<要執行的命令或人工步驟>
- 產品版本：<需更新／不需更新／待決；依 `docs/DEVELOPMENT.md` 說明原因、預計的 `versionName`／`versionCode`，以及 Android APK／MuMu smoke 是否適用>
- 風險／回退：<主要風險與恢復方式；沒有寫「無」>
- 待決問題：<需要我決定的事；沒有寫「無」>
```

你在 Issue 留言或當次對話明確指示按此範圍實作，才算核准。AI 記錄核准來源；若後續大幅改變範圍，重新向你確認。
